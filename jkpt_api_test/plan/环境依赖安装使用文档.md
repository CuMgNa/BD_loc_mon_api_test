# JKPT API 测试环境依赖安装与使用文档

## 1. 目的

本文档用于统一 `jkpt_api_test` 项目的环境安装与依赖使用方式，避免“本机能跑、换机失败”的问题。

---

## 2. 当前环境现状（基于实测）

- 当前默认解释器：`D:\python\python.exe`（全局 Python）
- 项目虚拟环境：`.\.venv\Scripts\python.exe`
- `.venv` 内已安装包很少（基本仅 `pip`）
- 项目目前可运行主要依赖于全局环境中已安装的包

结论：项目建议切换到 `.venv` 作为标准运行环境，并固定依赖清单。

---

## 3. 项目核心依赖（来自 `pyproject.toml`）

```toml
pytest>=7.0.0
```

## 4. 推荐安装步骤（Windows + PowerShell）

### 4.1 进入项目目录

```powershell
cd C:\Users\33606\Desktop\jkpt_api_test
```

### 4.2 创建虚拟环境（若已存在可跳过）

```powershell
python -m venv .venv
```

### 4.3 激活虚拟环境

```powershell
.\.venv\Scripts\Activate.ps1
```

激活后建议确认解释器路径：

```powershell
python -c "import sys; print(sys.executable)"
```

预期输出应包含：`jkpt_api_test\.venv\Scripts\python.exe`

### 4.4 升级基础工具

```powershell
python -m pip install -U pip setuptools wheel
```

### 4.5 安装项目依赖

> 方案 A（推荐，保持与 `pyproject.toml` 一致）

```powershell
pip install pytest requests pyyaml ddddocr pillow allure-pytest pytest-rerunfailures
```

> 方案 B（如果后续补充了 `requirements.txt`）

```powershell
pip install -r requirements.txt
```

## 5. Allure CLI 安装与验证

`allure-pytest` 仅负责生成结果文件，展示报告还需要 `allure` 命令行工具（Java 版 CLI）。

### 5.1 验证是否可用

```powershell
allure --version
```

如果输出版本号（例如 `2.39.0`），表示可用。

### 5.2 常用报告命令

```powershell
# 运行测试（根据 pytest.ini 自动写入 temps）
pytest -vs

# 生成静态报告
allure generate ./temps -o ./reports --clean

# 正确打开报告（HTTP服务方式）
allure open ./reports
```

> 不建议双击 `reports/index.html`，会因 `file://` 跨域限制出现页面长期 Loading。

---

## 6. 日常使用标准流程

每次开始工作建议按以下顺序：

1. 打开 PowerShell 并进入项目目录
2. 激活虚拟环境：`.\.venv\Scripts\Activate.ps1`
3. 运行测试：`pytest -vs`
4. 打开报告：`allure open ./reports` 或使用 `python run.py`

---

## 7. 故障排查

### 7.1 报错：`allure` 不是内部或外部命令

- 原因：Allure CLI 未安装或未加入 PATH
- 处理：安装 Allure CLI 并重启终端后重试

### 7.2 报告页面一直 Loading

- 原因：使用 `file://` 直接打开 `index.html`
- 处理：改用 `allure open ./reports` 通过 `http://localhost` 打开

### 7.3 模块找不到（如 `ModuleNotFoundError: ddddocr`）

- 原因：依赖装在全局环境，当前用的是 `.venv`（或相反）
- 处理：
  1. `python -c "import sys; print(sys.executable)"` 确认解释器
  2. 在当前解释器下重新执行 `pip install ...`

## 8. 团队协作建议

- 固化依赖文件（建议后续补 `requirements.txt` 与锁定文件）
- 新同事入场按本文档执行，确保环境一致
